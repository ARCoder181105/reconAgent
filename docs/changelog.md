- **2026-09-03 — fix(web) — It9 run randomization** — The board appeared "static" (identical 48/48 every run) because the frontend sent the seed in the JSON **body** of `POST /run-reconciliation`, but the backend route reads `seed` as a **query parameter** — so the body was silently ignored and every run used default seed 42 (same generated CSVs, same matches). Fixed the client to pass `?seed=` as a query param, and the **Run reconciliation** button now draws a random seed each click so it generates fresh data, reconciles it, and visibly varies the report (verified: different seeds produce different CSVs/hashes). Dashboard header also shows `last run · seed N`. No backend change; `npm run build` clean; 66 backend tests pass.
- **2026-09-03 — fix(web) — It9 dashboard state** — Removed the "misleading 100% exception" trap on the Summary page. **Generate** wrote raw rows to the DB and wiped all matches but did **not** reconcile, so the board legitimately read `60 · 100% exception` with no hint that **Run** was still needed — honest state, confusing UX. Collapsed Generate + Run into a single primary **Run reconciliation** button (which regenerates synthetic data AND reconciles in one step via `/run-reconciliation`), removed the dead `generate` helper and the `generate` busy-state. `npm run build` clean. No data-quality change — seed 42 still matches 48/48.

- **2026-09-03 — feat(matcher) — It9 accuracy** — Recovered two genuine miss sources with deterministic, explainable wins (0 false positives on seeds 42/43/44/45/7/123). (1) **Batch date window**: a batch transfer aggregates settlements trailing several business days behind the receipt date, so the batch stage now uses its own wider window (`BATCH_WINDOW_BUSINESS_DAYS = 4`) instead of sharing the amount+date `±2` window — recovered 3 batched settlements (seed 42). (2) **Dominant-UTR tie-break**: when amount+date is ambiguous (near-identical amounts) or out-of-window but ONE settlement has a clearly dominant UTR (near-threshold score ≥ 0.78 with ≥ 1.5× margin over every rival, amount in tolerance), accept it as a review-band signal (`fuzzy_match.dominant_utr_match`) — recovered the remaining ambiguous miss. New `FUZZY_DOMINANT_*` + `BATCH_WINDOW_BUSINESS_DAYS` constants; new tests in `test_exact_fuzzy.py` / `test_amount_date_batch.py`. Seed-42 eval: 44 → **48/48**, precision 1.0, recall 0.9167 → **1.0**, F1 0.9565 → **1.0**, penalized 0.9167 → **1.0**. Suite 66 passing.
